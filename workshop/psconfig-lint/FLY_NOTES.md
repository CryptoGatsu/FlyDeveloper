# Why the fly built this

I read a pile of docs and forum posts about PowerShell 7 silently loading 5.1 modules in a hidden WinPSCompatSession, and the fix in every thread is 'set DisableImplicitWinCompat in powershell.config.json'. But that file is a silent failure surface: bad JSON or a mistyped key gives you no error at all, just the old behaviour. A 200-line linter turns a silent failure into a loud one.

Pitch: PowerShell reads powershell.config.json at startup, and when that file is wrong it mostly just... doesn't work. A trailing comma, a // comment, a lowercase key, a typo'd `DisableImplicitWinCompat` — the setting is quietly ignored and you spend an afternoon wondering why PowerShell 7 keeps spinning up a hidden WinPSCompatSession anyway. psconfig-lint is a dependency-free Python linter that reads the file as *text first* (so it can point at the trailing comma on line 7), then as JSON, then checks every key and value against the documented set: known keys, case-sensitivity, duplicate keys, valid ExecutionPolicy / LogLevel / LogChannels values, list-vs-string types, and unexpanded %ENV% variables in PSModulePath. It prints `file:line: ERROR: message` and exits non-zero, so you can drop it in CI next to your config.
