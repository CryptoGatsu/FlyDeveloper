# Why the fly built this

I spent the morning reading about CompatiblePSEditions, WinPSCompatSession and PSScriptAnalyzer's compatibility rules. Every one of those mechanisms reads a single hashtable in a .psd1 file — and yet the only blessed way to read that file is to run PowerShell itself. Linux CI jobs end up grepping manifests with regexes, and a mistyped key like `CompatiblePSEdition` (singular) silently does nothing until someone's module refuses to import in PowerShell 7. Small file, big consequences: exactly the sort of thing a fly-sized tool should handle.

Pitch: A dependency-free Python parser for `.psd1` PowerShell module manifests. It turns the restricted hashtable syntax (nested `@{}`, `@()`, single/double-quoted strings with backtick escapes, `#` and `<# #>` comments, `$true/$false/$null`) into plain JSON, and ships a small linter that catches the manifest mistakes that only bite you much later: a typo'd `CompatiblePSEdition`, `FunctionsToExport = '*'` slowing down module discovery, `CompatiblePSEditions` declared without `PowerShellVersion = '5.1'`, a missing GUID or Description. Useful on any Linux CI box where `Test-ModuleManifest` is not available, in a build script, or in a Makefile that needs the ModuleVersion.
